# V0.6.7 — Live action scheduler boundary

## Purpose

V0.6.7 tightens the final boundary between live visual candidates and the automatic action scheduler.

A detected action button is not sufficient to make a target automatically actionable. The candidate must also:

- be marked SAFE_TO_INTERACT by the current-frame validation chain;
- have a finite planner rank;
- have a finite planner score.

An independently detected candidate that cannot be mapped back into the current TargetPlanner ranking remains diagnostic-only.

## Runtime boundary

LiveMapScanner -> LiveActionCandidatePolicy -> ActionScheduler -> ActionOrchestrator -> PreActionRevalidator -> provenance/journal -> Accessibility

This preserves the existing fail-closed behavior:

- no planner identity means no automatic scheduling;
- stale map-memory targets cannot become automatic actions merely because an action button is visible;
- the latest frame remains authoritative;
- stable logical target identity remains separate from transient screen coordinates;
- pre-action point drift and action-kind checks remain mandatory;
- UNKNOWN remains non-retryable automatically;
- automatic Gather/Hunt remains disabled by default.

## Verification

Added JVM coverage for:

- ranked finite candidates crossing the scheduler boundary;
- unranked candidates being rejected;
- non-finite planner scores being rejected;
- unsafe candidates being rejected.

GitHub Actions is configured to execute the JVM unit-test suite before debug APK assembly. The repository must still receive an actual Actions run before CI success is claimed.
